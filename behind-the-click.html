A page comes in pieces

Normally when you click on a link it doesn't download a complete website all at once. Your browser then asks for the HTML content. As it reads the document, it may request pictures, CSS files and Javascript independently.

  1. Your browser sends a requestt for a resource.
  2. The server processes the request.
  3. The server sends back an HTTP response.
  4. Your browser uses the response to build the page.

This accounts for the fact that a page can display its text before its pictures come up. Different resources may load in different time.

What does the conversation consist of?

A request describes what the client wants. A response reports the results and may include the requested content.

  • Method: the action requested, such as GET.
  • Target: the resource being requested.
  • Headers: extra information about the message.
  • Status code: the result reported by the server.
  • Body: content carried by a message, when present.

For instance, a browser can send a GET request for an image. A successful response can provide status code 200 and the image data in the body.

If HTTP forgets, why does your cart remember?

HTTP is stateless. It does not automatically recall past requests. A shopping website provides its own technique to link your visits.

Your server can deliver a cookie to be stored by your browser. Then your browser can send the cookie back with later requests. The cookie may iinclude an identification that ties you to shopping cart data on the server.

HTTP provides the rules for how messages are exchanged. The application keeps the cart in mind.

The fastest download may be the one you skip

The browser cache has copies of resources. If caching rules permit it, the browser can use a saved copy rather than dowloading it again.

Sometimes the browser will ask if a resource has changed. If it has not changed, the server can reply with 304 Not Modified. The browser then utilizes its copy again.

Cookies allow you to correlate requests with application state. Caching helps to reuse content. They serve various objectives in the same browsing experience.
